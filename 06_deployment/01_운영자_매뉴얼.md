# 운영자 매뉴얼

## 1. 운영 대상

- 대시보드: `06_deployment/dashboard_site`
- 데이터 단위: `physical_id` 기준 고유 OSM 보행 도로구간
- 현재 스냅샷: 현장조사 29개 구간, 2차 우선 확인 후보 10개
- 벤치 공백 기준: 300m·500m

이 서비스는 최종 벤치 설치 위치를 결정하지 않는다. 예상 보행 수요,
좌석 공백과 현장판정을 결합해 설치 우선 검토 순서를 제공한다.

## 2. 운영 화면

기본 화면은 다음 순서로 구성한다.

1. 현장검토·2차 후보·설치 가능·현장 제외 요약
2. 후보 검색과 판정 구간·공백 기준 필터
3. OSM 기반 후보 도로 지도
4. 후보별 모델 안정도·경로 중첩·좌석거리·현장근거
5. 방법론과 해석 제한

## 3. 운영 점검

데이터 갱신 후 다음을 확인한다.

- 후보 GeoJSON이 29개 고유 `physical_id`를 포함하는가
- 2차 검토순위가 1~10까지 중복 없이 연결되는가
- 모든 공간 객체가 `LineString`인가
- 설치 가능·조건부·설치 불가 건수가 Evaluation 보고서와 일치하는가
- CSV 다운로드 파일이 최신 산출물인가
- 지도 타일과 카카오맵·OSM 외부 링크가 열리는가

## 4. 장애 대응

- 지도가 회색으로 보이면 외부 OpenStreetMap 타일 접근 여부를 확인한다.
- 후보가 보이지 않으면 `public/candidates.geojson`의 존재와 JSON 형식을 확인한다.
- 숫자가 보고서와 다르면 데이터 갱신 스크립트를 다시 실행한 뒤 빌드한다.
- 배포본은 실시간 DB 연결이 아닌 게시 시점 스냅샷이다.

## 5. 표현 원칙

- “실제 노인 이동 경로” 대신 “고령자 예상 보행 수요·예상 경로”를 사용한다.
- 버스 이용량은 전체 연령 이용량의 대리변수라고 명시한다.
- 후보는 “설치 우선 검토구간”으로 표현한다.
- 현장 세부근거가 미완료된 후보는 “예비 우선”으로 표현한다.
