# 데이터 갱신 및 재분석 절차서

> **버전 안내:** 아래 절차는 2026-07-27 대시보드 파이프라인을 기준으로 작성됐다. 최신 v2 결과를 다시 게시할 때는 `05_evaluation/scripts/integrate_v2_field_review_results.py` 실행과 40개 후보·8개 직접 설치 검토군 검증을 추가해야 한다.

## 1. 갱신 순서

1. 원천 공공데이터와 OSM 보행망을 갱신한다.
2. Data Understanding 품질 검사를 다시 실행한다.
3. Data Preparation 통합 데이터를 다시 생성한다.
4. Modeling의 예상 경로·좌석 공백·후보 순위를 다시 계산한다.
5. Evaluation 민감도 분석과 현장조사 고유 후보표를 다시 만든다.
6. 현장조사 완료 CSV를 프로젝트 루트에 넣는다.
7. 현장조사 통합 Evaluation과 대시보드 데이터 갱신을 실행한다.
8. 웹사이트를 빌드하고 새 버전을 게시한다.

## 2. 대시보드 데이터 갱신

프로젝트 루트에서 다음을 실행한다.

```bash
python3 06_deployment/scripts/refresh_dashboard_data.py
```

스크립트는 최신 `dalseo_field_review_completed*.csv`를 선택하고,
Evaluation을 재실행한 뒤 다음 파일을 대시보드에 복사한다.

- `public/candidates.geojson`
- `public/priority_top10.csv`
- `public/all_candidates.csv`

검증 결과는 `06_deployment/qa/deployment_data_summary.json`에 저장한다.

## 3. 재현성과 버전 관리

- 원천 파일명과 기준일을 유지한다.
- 현장조사 완료 CSV는 수정하지 않고 새 버전으로 보관한다.
- OSM 수집일, 공공데이터 기준일과 분석일을 보고서에 기록한다.
- 배포 화면의 스냅샷 날짜를 갱신한다.
- 게시된 결과가 실시간 연결이 아닌 고정 스냅샷임을 표시한다.

## 4. 갱신 중단 기준

다음 조건이면 배포를 중단한다.

- 후보 ID 누락·중복 또는 원본 후보 속성 변경
- 허용되지 않은 현장판정 값
- GeoJSON 29건 또는 TOP 10 순위 연결 실패
- 좌표계 오류나 `LineString` 이외 공간 객체
- 보고서와 대시보드의 판정 건수 불일치
